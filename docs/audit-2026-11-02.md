# Audit del 2 novembre 2026

## Correzioni

- CSP: `unsafe-eval` solo in sviluppo; `object-src none`. `unsafe-inline` resta
  necessario alle pagine prerenderizzate: non rimuoverlo senza un progetto CSP
  con nonce (rendering dinamico) o hash compatibili con la build.
- Menu mobile con nome accessibile, stato di apertura, pannello identificato e
  chiusura con Escape dal pannello con ritorno del focus al pulsante.
- Registrazione: minimo di 8 caratteri anche nel browser; istruzioni username
  coerenti con la normalizzazione server in minuscolo. Il server già imponeva
  il minimo e normalizzava le maiuscole: non era una falla di validazione server.
- Recupero password: collegamento ai contatti. La verifica dell'identità resta
  una procedura degli educatori/operatori, non un reset pubblico via email.
- Cookie tecnici: unico pulsante informativo, nessuna falsa scelta di consenso;
  mantiene le precedenti chiusure e funziona anche con localStorage bloccato.
- Login: input limitati prima di scrypt; accesso negato se il database non
  permette di contare o azzerare i tentativi. Il contatore resta non atomico:
  le richieste concorrenti richiedono un limiter transazionale separato.
- Sessioni: confronto con `password_cambiata_at`, oltre a scadenza e token;
  una cancellazione fallita non mantiene valide le sessioni precedenti al reset.
- API questionario: JSON null, array e valori primitivi restituiscono 400.

## Revisione del codice

L'area legge le compilazioni usando l'ID della sessione. L'API assegna il
proprietario dalla sessione e ammette solo studenti per le fasi personali;
non prende account_id dal client. Le azioni staff verificano il ruolo sul
server. La migrazione abilita RLS senza policy e revoca i privilegi pubblici.
Questa revisione non verifica l'effettiva applicazione delle migrazioni live.

## Interventi ancora da definire

- Il titolare deve confermare le basi giuridiche di account, questionari,
  avatar e valutazione educativa e approvare la relativa informativa IT/EN.
  La sezione attuale tratta solo cookie e non basta a descrivere questi usi.
  Non si modifica una base giuridica per deduzione tecnica.
- Specificare termine del progetto/conservazione, destinatari e fornitori,
  eventuali trasferimenti, gestione dei consensi dei tutori e assistenza.
- Il limiter per IP (compresa la registrazione) è in memoria: non è globale
  fra istanze Vercel. Valutare un contatore atomico condiviso mantenendo
  soglie compatibili con una classe dietro un solo IP e minimizzando i dati.
- Eseguire test con account sintetici in ambiente di test: isolamento tra
  due studenti, ruoli staff, sessioni, reset e blocco dei codici classe.
- Nessun tentativo di login, registrazione o scrittura al database live
  effettuato durante questo intervento. Nessuna migrazione richiesta.
